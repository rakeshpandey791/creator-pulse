## How to use this tracker

This file is the execution tracker. `ENGINEERING_TASKS.md` remains the detailed task specification and source of acceptance criteria.

Use one task ID consistently in the branch, commits, review, QA report and defect reports. Do not start a task until its dependencies are complete.

### Status values

- `NOT_STARTED` — dependencies or assignment are not complete.
- `READY` — dependencies are complete and the task can be assigned.
- `IN_DEVELOPMENT` — Software Engineer Agent is implementing it.
- `IMPLEMENTATION_COMPLETE` — implementation and developer tests are reported.
- `CODE_REVIEW` — Code Review Agent is independently reviewing the diff.
- `CHANGES_REQUESTED` — review found blocking changes.
- `QA_READY` — review passed and the task is ready for validation.
- `QA_IN_PROGRESS` — Manual QA Agent is testing the task.
- `QA_FAILED` — QA found a reproducible defect.
- `QA_PASSED` — acceptance criteria passed.
- `MERGED` — approved changes are merged.
- `COMPLETE` — task is merged and its Definition of Done is evidenced.
- `BLOCKED` — progress requires an explicit decision, dependency or external change.

### Agent gates

1. Software Engineer Agent writes only the assigned task scope, adds tests and reports validation.
2. Code Review Agent is read-only by default and returns `APPROVE` or `CHANGES_REQUESTED`.
3. Manual QA Agent validates the user journey in Chrome where applicable and records evidence; backend/worker tasks also require automated/API/database validation.
4. A task cannot reach `COMPLETE` without implementation evidence, review approval, QA result and Definition of Done confirmation.

## Agent handoff checklist

### Software Engineer Agent

- [ ] Read the task, dependencies and referenced source documents.
- [ ] Confirm the task is `READY` and no conflicting worktree changes exist.
- [ ] Implement only the assigned scope.
- [ ] Add/update tests and documentation.
- [ ] Run lint, type-check, targeted tests and build as applicable.
- [ ] Update the task row to `IMPLEMENTATION_COMPLETE` and attach the change summary.

### Code Review Agent

- [ ] Read the task specification and acceptance criteria independently.
- [ ] Inspect the complete diff, not only the summary.
- [ ] Check architecture boundaries, security, privacy, data ownership and scope.
- [ ] Check test quality and missing failure cases.
- [ ] Record findings with severity and file/location.
- [ ] Set `Review` to `APPROVE` or `CHANGES_REQUESTED`.

### Manual QA Agent

- [ ] Confirm review approval and test environment.
- [ ] Execute the task’s acceptance workflow in Chrome when UI is involved.
- [ ] Check responsive, loading, empty, success and failure states.
- [ ] Validate persistence after refresh and relevant authorization boundaries.
- [ ] Record reproducible defects with expected/actual behavior and evidence.
- [ ] Set `QA` to `PASSED` or `FAILED`.

## Defect loop

Any review or QA defect returns the task to `IN_DEVELOPMENT`. The Software Engineer Agent fixes only the reported scope, then targeted tests, review and QA are repeated. A task is not complete because a workaround was manually verified; the underlying acceptance criterion must pass.
