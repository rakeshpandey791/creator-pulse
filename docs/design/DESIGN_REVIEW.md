# CreatorPulse Design Review

**Status:** Generated drafts awaiting user review  
**Screens approved:** None

## 1. Review checklist

### Product alignment

- [x] Discovery is the central experience.
- [x] MVP screens exclude direct publishing and connected social accounts.
- [x] Evidence, score explanations, freshness and competition are represented.
- [x] Hooks, scripts and CTAs are part of the idea workflow.
- [x] Credits, usage limits and subscription states are represented.
- [x] Optional feedback is represented.
- [x] Seven launch languages and the approved launch niche set are represented in content/context requirements.

### UX quality to verify in prototypes

- [x] First useful idea is reachable quickly on mobile in the generated Today variant prompt; visual review remains pending.
- [ ] Feed cards communicate value without excessive density.
- [ ] Evidence limitations are understandable.
- [ ] Score dimensions are accessible without color dependence.
- [ ] Script generation progress and failure recovery are clear.
- [ ] Credit cost is visible before generation.
- [ ] Language switching does not cause accidental content loss.
- [x] Desktop and mobile layout intent preserves the same primary action in the generated prompts; visual review remains pending.
- [ ] Empty, loading, partial-data and error states are visually coherent.
- [ ] Typography renders all seven supported languages reliably.
- [ ] Location permission is optional, explicit, coarse-grained and removable.
- [ ] Local trend cards show source, freshness, active location and evidence limitations.
- [ ] Gemini trend interpretation is visibly separated from source observations.
- [ ] The creator can provide a one-sentence brief before full script generation.
- [ ] Weak or unavailable local coverage falls back clearly without fabricated certainty.
- [ ] New-script flow uses one question per step, onboarding defaults and one clear primary action.
- [ ] Hindi/Bhojpuri or the selected regional language is primary in labels and examples.
- [ ] The creator can understand the pipeline without seeing model, retrieval or prompt terminology.
- [ ] Slow-connection, retry and preserved-draft states are clear and non-destructive.
- [ ] The design leaves room for optional voice input without making it a required dependency.
